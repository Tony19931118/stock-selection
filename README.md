"# 台股低於一年高低點中間值選股

## 1. 專案目的

取得台灣股票市場的即時價格與最近半年或一年的歷史行情，計算每檔股票所選期間最高價與最低價的中間值，並找出目前即時價格低於該中間值的股票，以表格呈現供使用者篩選。

本功能僅提供市場資料整理與條件篩選，不構成投資建議。

## 2. 名詞定義

- **即時價格**：以查詢當下可取得的最新成交價為主。非交易時段則使用資料來源提供的最近一筆成交價，並標示資料時間。
- **查詢期間**：可選擇以查詢日往前回溯六個月或十二個月，取資料來源可取得的交易日資料。
- **一年最高價**：該股票在最近一年區間內每日最高價的最大值。
- **一年最低價**：該股票在最近一年區間內每日最低價的最小值。
- **中間值**：`(一年最高價 + 一年最低價) / 2`。
- **差異百分比**：`(中間值 - 即時價格) / 中間值 * 100%`。僅列出結果大於 0 的股票，因此數值代表即時價格低於中間值的幅度。

## 3. 功能需求

### 3.1 股票範圍

1. 股票範圍限定為台灣證券交易所（TWSE）掛牌的上市普通股。
2. 排除 ETF、ETN、權證、受益憑證、特別股、TDR、指數及其他非普通股商品。
3. 股票清單應包含目前上市股票，並保留股票代號與名稱。
4. 納入處置股與暫停交易股票；若資料來源能提供股票狀態，應保留其狀態供使用者識別。

### 3.2 資料取得

1. 取得每檔股票的基本資料：
   - 股票代號
   - 股票名稱
   - 市場別（固定為上市）
2. 取得每檔股票最近一年每日歷史資料，至少包含：
   - 交易日期
   - 每日最高價
   - 每日最低價
3. 取得每檔股票的最新成交價與報價時間。
4. 即時資料與歷史資料必須記錄來源、查詢時間及資料時間，便於追溯。
5. 應處理 API 限流、逾時、暫時性錯誤與單一股票資料缺漏；單一股票失敗不得使全部結果失敗，但需在結果中顯示處理摘要或錯誤紀錄。
6. 歷史資料不足一個交易日，或缺少最高價／最低價／即時價格時，不得計算該股票，並列入排除原因。

### 3.3 資料處理

對每檔符合資料完整性要求的股票：

1. 以最近一年歷史資料計算：
   - `一年最高價 = max(每日最高價)`
   - `一年最低價 = min(每日最低價)`
   - `中間值 = (一年最高價 + 一年最低價) / 2`
2. 將最新成交價與中間值比較。
3. 僅保留 `即時價格 < 中間值` 的股票。
4. 計算差異百分比：
   - `差異百分比 = (中間值 - 即時價格) / 中間值 * 100`
5. 差異百分比顯示至小數點後 2 位，計算過程不得因顯示格式而提早四捨五入。
6. 結果預設依差異百分比由高至低排序；若相同，依股票代號由小至大排序。

### 3.4 查詢與更新

1. 使用者可執行一次查詢，系統產生當次篩選結果。
2. 使用者可指定查詢日期；未指定時使用系統日期。
3. 使用者可重新整理以取得最新即時價格。
4. 應顯示本次資料更新時間，以及目前是否為交易時段。
5. 若即時報價不是交易中即時成交價（例如休市時使用最近成交價），應明確標示「最近成交價」及其時間。
6. 提供 Excel 匯出功能，匯出內容至少包含結果表格的股票代號、股票名稱及差異百分比；若畫面顯示驗證欄位，也應一併匯出。
7. 第一階段不提供自動更新、通知或歷史查詢紀錄功能。

## 4. 輸出需求

### 4.1 主要結果表格

結果表格至少包含以下欄位：

| 欄位 | 說明 |
| --- | --- |
| 股票代號 | 台股股票代號 |
| 股票名稱 | 股票中文名稱 |
| 差異百分比 | 中間值高於即時價格的百分比，顯示至小數點後 2 位 |
| 即時價格 | 本次使用的最新成交價 |
| 即時成交量 | 查詢當下可取得的最新成交量 |
| 一年最高價 | 最近一年每日最高價的最大值 |
| 一年最低價 | 最近一年每日最低價的最小值 |
| 中間值 | 一年最高價與最低價的平均值 |
| 報價時間 | 即時價格的資料時間 |

### 4.2 無結果與錯誤

1. 沒有股票低於中間值時，顯示「查無符合條件的股票」，不得顯示空白畫面。
2. 所有資料來源無法取得時，顯示明確錯誤訊息與建議重試，不得產生看似正常的空結果。
3. 顯示成功處理、符合條件及排除數量；必要時提供排除原因。

## 5. 非功能需求

1. **正確性**：同一批輸入資料的計算結果必須可重現，價格計算使用數值型別，不得以字串排序。
2. **資料一致性**：即時價格、歷史區間與查詢時間必須在結果中可辨識。
3. **可靠性**：單檔資料取得失敗應隔離處理，並保留錯誤紀錄。
4. **安全性**：API 金鑰（若資料來源需要）必須由環境變數或安全設定提供，不得寫入程式碼或版本控制。
5. **可維護性**：資料來源介面、計算邏輯與輸出呈現應分離，未來可替換資料來源。
6. **效能**：應支援批次取得或快取歷史資料，避免每次重新查詢造成不必要的 API 請求。

## 6. 驗收條件

1. 給定一檔股票一年最高價 `120`、最低價 `80`、即時價格 `90` 時，中間值為 `100`，結果應列出且差異百分比為 `10.00%`。
2. 即時價格等於中間值時，不得列出該股票。
3. 即時價格高於中間值時，不得列出該股票。
4. 查詢結果每筆至少包含正確的股票代號、名稱及差異百分比。
5. 結果排序必須符合差異百分比由高至低。
6. 缺少任何必要價格資料的股票不得列入結果，且應可追蹤排除原因。
7. 休市查詢時，結果必須顯示報價實際時間，且不得將最近成交價誤標示為交易中即時價。
8. 無符合股票、部分資料失敗及全部資料失敗三種情境，均須顯示清楚且可理解的狀態訊息。

## 7. 已確認範圍

- 即時價格以最新成交價為主；非交易時段使用最近一筆成交價並標示時間。
- 提供 Excel 匯出功能。
- 第一階段不提供自動更新、通知或歷史查詢紀錄。
- 僅處理上市股票；不處理上櫃與興櫃股票。上市處置股與暫停交易股票仍納入。

## 8. 第一階段實作狀態

- 前端使用 React、Next.js App Router 與 TypeScript。
- `GET /api/stocks?months=6` 或 `GET /api/stocks?months=12` 由伺服器端取得 TWSE 上市普通股清單，再以 Yahoo Finance Chart API 取得所選期間每日最高價、最低價、最新成交價與即時成交量。
- API 會計算所選期間最高價、最低價、中間值與差異百分比，只回傳即時成交價低於中間值的股票。
- 單檔資料請求採 12 檔並行；個別逾時或資料缺漏會排除該檔並回傳失敗數量，不影響其他股票。
- 伺服器結果快取 5 分鐘；目前未實作自動更新、通知或歷史查詢紀錄。
- 結果表格支援搜尋、差異百分比排序及每頁 10、25、50 筆切換。
- 即時成交量可依升冪或降冪排序。
- 股票代號與股票名稱分欄顯示；可依即時成交價 100 元以下及差異百分比 50% 以上篩選。
- 目前匯出按鈕產生含 UTF-8 BOM 的 CSV，Excel 可直接開啟；後續可替換為原生 `.xlsx` 格式。
